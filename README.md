# Портал управления портфелем AI-инициатив (v2)

Прототип с моделью данных «инициатива → плановые ресурсы (человеческие/технические) → выгода →
согласование руководителем → комментарии». Отдельный проект, не связан с более ранней версией
портала в `ai_champions/` — модели данных несовместимы.

## Архитектура

```
/backend/   FastAPI + SQLAlchemy + SQLite, весь REST API
/frontend/  Статический SPA (vanilla JS/HTML/CSS), отдаётся через nginx
/data/      Volume с файлом SQLite (создаётся автоматически)
docker-compose.yml
```

Frontend (nginx, порт **8080**) отдаёт статику и проксирует `/api/*` на backend, так что браузер
обращается к одному origin. Backend также опубликован напрямую на порту **8000**
(Swagger: `/docs`).

## Запуск

```bash
docker compose up -d --build
```

- Портал: http://localhost:8080
- API напрямую: http://localhost:8000/docs

При первом старте backend создаёт таблицы (`Base.metadata.create_all`) и наполняет БД
справочниками и демо-данными (`app/seed.py`): 3 подразделения, 9 ресурсов (5 человеческих,
4 технических), 6 сотрудников (2 чемпиона, 2 руководителя, 1 PM, 1 топ-менеджер) и 5 демо-инициатив
в разных статусах согласования. Данные хранятся в `./data/app.db` на хосте и переживают
перезапуск контейнеров.

Пересобрать и пересоздать контейнеры с нуля:

```bash
docker compose up -d --build --force-recreate
```

Полностью сбросить данные: `docker compose down && rm -rf ./data`.

## Роли и вход

Пароля нет — на первом экране выбирается сотрудник из выпадающего списка (все сотрудники видны
сразу, роль определяется автоматически по выбранному сотруднику). ID сотрудника хранится в
`sessionStorage` и передаётся backend'у в заголовке `X-Employee-ID` при каждом запросе.

- **champion (AI-чемпион)** — создаёt инициативы, задаёт плановые ресурсы и ожидаемую выгоду,
  видит и редактирует только свои инициативы.
- **head (руководитель подразделения)** — видит инициативы только своего подразделения (сервер
  сам подставляет фильтр по department_id руководителя, даже если передать другой), может
  согласовать / отклонить / отправить на пересмотр.
- **pm** — видит все инициативы с фильтрами, может удалять любые.
- **top (топ-менеджмент)** — портфельный дашборд и просмотр всех инициатив без права
  редактирования.

## Правила агрегации ресурсов в дашборде

Разные ресурсы измеряются в разных единицах (человеческие — чел-часы, CPU — ядра, GPU — ядра в
H100-эквиваленте, RAM — ГБ, Disk — ТБ), поэтому портфельный дашборд **не складывает их в одно
число**: человеческие ресурсы (все в чел-часах) показаны одним графиком, технические ресурсы и
выгода — таблицами с явной единицей измерения на каждой строке.

## REST API (основное)

| Метод | Путь | Описание |
|---|---|---|
| GET | `/departments`, `/employees`, `/resources` | справочники |
| GET/POST | `/initiatives` | список (фильтры `champion_id`, `department_id`, `is_approved`) / создание (только роль champion, от своего имени) |
| GET/PUT/DELETE | `/initiatives/{id}` | карточка / обновление (только владелец-чемпион, ресурсы и выгода перезаписываются) / удаление (владелец или PM) |
| POST | `/initiatives/{id}/approve` | согласовать (только руководитель своего подразделения) |
| POST | `/initiatives/{id}/reject` | отклонить, комментарий обязателен |
| POST | `/initiatives/{id}/revision` | отправить на пересмотр, комментарий обязателен |
| GET/POST | `/initiatives/{id}/comments` | комментарии к инициативе |
| GET | `/notifications` | уведомления текущего сотрудника |
| POST | `/notifications/{id}/read` | отметить прочитанным |
| GET | `/dashboard/head` | для руководителя: pending/approved списки и счётчики по своему подразделению |
| GET | `/dashboard/top` | портфель целиком: счётчики, ресурсы и выгода по типам (с единицами), распределение по подразделениям |

Авторизация упрощённая: заголовок `X-Employee-ID` определяет текущего сотрудника; ключевые
действия (создание — только champion, согласование — только head своего подразделения, удаление —
владелец или pm) проверяются на backend.

## Локальная разработка без Docker

```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
DATA_DIR=./data uvicorn app.main:app --reload --port 8000
```

```bash
cd frontend
python3 -m http.server 8080
```

При запуске без nginx-прокси поменяйте `API_BASE` в `frontend/script.js` с `/api` на
`http://localhost:8000`.
